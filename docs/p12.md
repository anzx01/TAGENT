产品需求文档：智能操作助手（极简版）
版本：1.1
产品定位：一个看演示就能自动学会并替你完成电脑操作的智能助手，全程无需编程、无需人工配置规则。

1. 产品要解决的问题
   人们每天重复着大量有规律的电脑操作（网页填表、数据搬运、系统操作等）。

现有自动化工具要么需编程，要么只能死板回放坐标，无法适应界面和数据的自然变化。

用户真正需要的是：演示一两遍，它就能理解任务，并生成一个能适应变化、稳定执行的机器人。

本产品将整个过程极度简化：录制->自动学习->生成Agent->执行，用户操作减至最少，一切智能推断由系统自动完成。

2. 用户与核心场景
   目标用户：所有需要重复执行电脑操作，但无编程能力的办公人员。

典型场景：

每天登录商家后台，查询新订单，将地址发给仓库，等待仓库回复快递单号并回填至系统（如国铁商城）。

从财务系统下载报表，整理后邮件发送。

定期登录多个网站检查状态并截图存档。

用户期望：像教同事一样，做一遍给它看，它就能独立上岗。

3. 产品核心工作流（极简闭环）
   整个产品仅围绕一个极简闭环：

录制（一次或两次） -> 自动学习与Agent生成 -> 一键执行/定时执行 -> 执行中自动纠错/学习

用户只需主动做三件事：

点“开始录制”，正常操作一遍任务。

点“执行”，让Agent试运行一次，如果不完美，接管纠正一次（Agent会自动学会这次纠正）。

后续让它定时或手动自动运行。

其它所有中间环节：分析步骤、推断规则、生成流程、适应变化，全部由系统自动完成，无需用户干预。

4. 功能需求（极简设计）
   4.1 一键录制
   启动方式：悬浮条上点击 “录制新任务”，开始后台静默录制。

录制内容：系统自动捕获全屏变化、鼠标点击、键盘输入、窗口切换等所有操作。

停止录制：用户操作完成后，点击 “停止录制并保存”。

多遍演示（可选）：若同任务存在不同分支（如有时有订单，有时无），用户可追加录制第二次，勾选“追加到同一任务”，系统自动合并理解。

合并判定依据：系统依据两次录制的起始与结束应用/页面是否一致来判定是否为同一任务的不同分支。若起始或结束环境明显不同，系统将提示用户“这看起来像另一个任务，是否新建”，避免误合并。

4.2 全自动学习与Agent生成
当用户点击“保存”后，系统在后台自动开始处理，无需用户任何操作，过程如下：

提取关键帧与动作：自动识别有意义的操作步骤，忽略无意义的鼠标漂移。

理解任务目标与决策：V1 的“理解”落地为以下可验收的能力：

识别操作步骤序列（如“打开订单系统->查找未处理订单->获取订单信息->填写物流信息->提交”）。

标注每一步中的可变数据点（见下条“数据泛化”）。

标注关键决策点（如“筛选出状态为待发货且没有单号的订单”）。

数据泛化机制：录制中出现的所有具体数据值（如订单号、收货地址、联系人），系统默认视为“可变占位符”，而非固定值。执行时按当前界面实际内容进行匹配与填入，从而适应每天变化的数据。固定值（如固定的系统网址、固定的菜单入口）由系统自动识别并保留。这一机制是 Agent 能跨天稳定运行的前提。

生成Agent：系统自动打包成一个可独立运行的 “技能机器人”。

学习完成后，系统简单提示：“我已学会『处理国铁发货』，您可以试运行一次。” 不展示复杂的流程图，不要求用户确认规则。

4.3 极简执行与监控
任务库：学习完成的Agent显示在主界面的卡片列表里，每张卡片只有名称、状态、一个 “运行” 按钮和一个 “定时” 开关。

运行：点击运行，Agent在后台静默执行（或显示一个微缩小窗）。

状态提示：

正常运行：小窗显示当前步骤简述（如“正在查询今日订单”）。

遇到不确定：小窗变为黄色，并暂停请求用户注视。此时用户可立即接管纠正。

遇到阻塞：变红并请求人工介入。

执行中的等待机制：当任务需要等待外部事件（如等待仓库在微信回复快递单号）时，Agent在该步骤进入轮询等待状态，定期检查目标窗口是否有新内容，不连续点击。小窗显示“正在等待回复…”，用户也可随时手动点“已收到，继续”。这避免了异步等待场景下的空转与误操作。

定时：支持每日/每隔X小时自动执行。

4.4 智能自我修复（人在回路，一键纠错）
这是“越用越聪明”的核心，设计极度简化：

当Agent执行中暂停请求帮助时，用户只需 接管操作，完成正确步骤，然后点“继续，并记住我的做法”。

系统自动捕获这次纠正的前后状态，将新规则融合进该Agent的知识库，无需用户手动修改任何配置。

下次遇到类似情况，Agent将自动使用新学到的策略。

整条流程跑偏的兜底：若Agent在试运行阶段就整条流程走偏、局部接管成本过高，用户可点“重新演示此任务”，从当前出错步骤起重新录制一小段，系统将其作为该步骤的替代规则合并，无需重录整个任务。这比硬接管更省事，也降低了首次试用的挫败感。

4.5 安全与隐私自动化
所有录制数据（截图、操作）默认加密存储在本地。

系统自动检测可能的密码输入框，执行到此处时默认暂停，由人工输入一次。

密码默认不保存、不自动填充。“加密保存以供后续自动填充”作为显式的高级选项，需用户主动开启并单独确认，确保隐私默认倾向为最小化收集。

5. 非功能性要求（保持简洁）
   性能：录制时CPU占用<5%，不影响用户正常操作；执行时后台智能调度。

兼容：支持Windows 10/11主流应用，对浏览器（Chrome/Edge）深度优化。

V1 跨应用支持边界：V1 明确支持“浏览器↔浏览器”及“浏览器↔常用桌面应用（微信、邮件客户端、Office）”的组合流转。对于不支持的组合（如冷门行业软件、需要管理员权限的系统操作），在录制时即提示“该应用暂不在支持范围”，避免承诺过宽导致执行失败。

交互语言：全程自然语言提示，无技术术语。

6. 与“过度设计”的明确切割
   以下功能不在V1.0范围内，以确保产品聚焦：

❌ 任务流程图可视化编辑。

❌ 手动配置决策规则或条件。

❌ 复杂的多Agent协同编排。

❌ 技能市场或分享功能（未来考虑）。

❌ 自然语言描述生成任务（V1仅支持演示学习）。

❌ 产品长期愿景、多Agent生态等方向性内容不在本 PRD 内展开，另立文档。

我们只做一件事：让人通过演示来教，让Agent自己去理解，然后自动执行。一切编辑、配置、优化都在“接管纠正”的一瞬间自然完成。

7. 成功标准
   用户从开始录制到Agent首次成功执行一个跨应用任务（如国铁发货场景）的总耗时 <15分钟（含录制2次+试运行+一次纠错）。

学习质量早期里程碑：Agent 首次试运行（0 次纠错）的自主成功率 > 50%。用于在学习阶段尽早判断生成质量，不达标时引导用户追加一次演示。

经过最多3次纠错后，Agent对该任务的自主成功率 > 90%。

用户无需阅读帮助文档，即可独立完成首次任务自动化。

本版修订说明（相对 v1.0）：
1. 明确数据泛化机制（4.2），让“适应变化”有可验收口径。
2. 补充执行中的等待/轮询机制（4.3），覆盖异步等待场景。
3. 增加整条流程跑偏时的“重新演示此任务”兜底（4.4）。
4. 明确多遍演示的合并判定依据（4.1），防止误合并。
5. 密码默认改为不保存，加密保存作为显式高级选项（4.5）。
6. 明确 V1 跨应用支持边界（第5节），避免承诺过宽。
7. 增加“首次试运行 0 纠错成功率 >50%”早期里程碑（第7节）。
8. 明确 V1“理解任务”的落地能力（4.2），避免黑盒承诺无法验收。
