智能操作助手 开发计划
版本：2.0
基于 PRD v1.1（p12.md），综合 GitHub 优秀开源项目借鉴制定。
原则：不过度设计，用最小路径跑通"录制->理解->执行->自愈"闭环。

==================================================
一、参考项目与借鉴要点
==================================================

按匹配度排序，重点借鉴前三个。

1. AI Mime (github.com/prakhar1114/ai_mime, MIT) ★★★★★
   "Record a task once. Run it forever." -- 与我们需求几乎完全一致。
   流程：Record -> Reflect(语义工作流) -> Optimize(优先确定性脚本) -> Build Skill -> Run/Heal(自愈打补丁)
   借鉴：确定性优先+agent兜底的混合执行；运行中断时自愈而非报错；产物目录可检查(recordings/workflows/runs)
   差异：仅 macOS，我们需 Windows + 定时调度。

2. skillwright (github.com/gericke98/skillwright, MIT) ★★★★☆
   "Show your browser a task once. Get a skill any agent can run - forever."
   借鉴：
   - 执行三级降级：确定性脚本 -> 选择器栈 -> LLM自愈
   - 自愈信任机制：先隔离试用，多次验证后才固化为正式规则（防错误修复污染）
   - 安全效果标签：每步标 readonly/mutating/destructive，破坏性操作需确认
   差异：仅浏览器。

3. ScreenClaw (github.com/GinSing1226/ScreenClaw, MIT) ★★★★★
   Tauri 2.0 + Python，Windows/中文/录制，技术栈与场景最接近。
   借鉴（可直接参考代码）：
   - Tauri+Python sidecar 集成方式
   - background 输入注入(PostMessage/SendMessage，不抢鼠标键盘)
   - 百分比坐标网格(分辨率无关)
   - 录制 API(start/stop/status，每步捕获截图+坐标+操作)
   - 安全：token认证、进程黑名单

4. OpenAdapt (github.com/OpenAdaptAI/OpenAdapt, 1.7k stars, MIT) ★★★★☆
   演示编译器：Record -> Compile -> Replay -> Governed Repair。
   借鉴：健康运行零模型调用；governed repair(修复是版本化变更，可回滚)；fail-closed(不确定就停，不猜)
   不借鉴：企业级 effect verifier 体系过重，V1 不做。

5. OpenClaw-RPA (github.com/leow3lab/rpa, MIT) ★★★★☆
   借鉴：编译为独立 Python 脚本零 token 回放；session 持久化(手动过一次 2FA，保存 cookie 后续自动注入)

6. Microsoft Skill Recorder (github.com/microsoft/skill-recorder, 1.5k stars) ★★★☆☆
   借鉴：录制状态机(防竞态)；多采集器(窗口跟踪+URL+变化帧截图+剪贴板)；录制时不录密码/Token

7. rpa-self-healing-poc (github.com/Forever5471/rpa-self-healing-poc) ★★★★☆
   借鉴：元素多维指纹(文本/属性/位置)，改版后按置信度召回最相似候选，置信度低则请求人工

8. OmniParser (github.com/microsoft/OmniParser, 21.7k stars, MIT) ★★★☆☆
   屏幕解析组件(YOLO检测+描述)。作为 V1 之后的可选感知兜底，不进 V1 核心。


==================================================
二、核心决策
==================================================

决策1：执行模型 = 确定性回放 + 受控自愈（非每步LLM）
  录制编译成确定性脚本正常执行；仅在卡住时用 LLM 自愈并打补丁。
  理由：AI Mime/skillwright/OpenAdapt 均验证此模型在可靠性、成本、速度上远胜"每步问LLM"。

决策2：技术栈 = Tauri 2.0 + Python sidecar
  ScreenClaw 已验证该栈在 Windows 可行；Tauri 体积小、Web UI 易做极简交互。

决策3：元素定位 = 两级（V1不做视觉解析）
  一级：Windows UI Automation（可访问性树，最稳）
  二级：坐标 + OCR 文本兜底（借鉴 ScreenClaw 百分比坐标）
  OmniParser 视觉解析留作 V2，V1 不引入额外模型依赖。

决策4：纠错记忆 = 简单纠错库（不做双重记忆）
  每次纠错存为一条 {触发状态, 正确动作, 结果}，下次遇到相似状态直接复用。
  不做 Agent-S 式的"叙事记忆+情景记忆"分层，V1 不需要。

决策5：登录/2FA = 会话持久化
  手动过一次，保存会话，后续自动注入（借鉴 OpenClaw-RPA）。


==================================================
三、系统架构
==================================================

对齐 AI Mime 的简洁流水线，不拆多余分层。

┌───────────────────────────────────────────┐
│  悬浮条 / 任务库 UI（Tauri Web 前端）       │
│  录制按钮 | 任务卡片 | 状态小窗 | 定时开关   │
└──────────────────┬────────────────────────┘
                   │ Tauri IPC
┌──────────────────▼────────────────────────┐
│  Python 核心 (FastAPI sidecar)             │
│                                           │
│  录制 -> 编译 -> 执行 -> 自愈              │
│                                           │
│  ┌────────┐  ┌────────┐  ┌────────┐      │
│  │ 录制器  │->│ 编译器  │->│ 执行器  │      │
│  └────────┘  └────────┘  └───┬────┘      │
│                             │ 失败       │
│                          ┌──▼──────┐     │
│                          │ 自愈器   │     │
│                          └─────────┘     │
│                                           │
│  底层能力：                                │
│  - 事件监听(pynput) + 截图(mss)            │
│  - UI Automation(uiautomation)            │
│  - 输入注入(background优先, pyautogui兜底)  │
│  - 纠错库(SQLite)                          │
└───────────────────────────────────────────┘

数据流：

录制：用户操作 -> 捕获(截图+事件+可访问性快照) -> recordings/
停止 -> 编译器分析 -> 生成 task(步骤序列+定位证据+可变数据标注)

执行：task -> 执行器逐步重放
  每步：用证据定位元素 -> 执行动作 -> 截图验证
  失败/不确定 -> 暂停(黄) -> 请求人工
  人工接管纠正 -> 自愈器存入纠错库 -> 打补丁到 task

任务产物结构（轻量）：
  tasks/<task_id>/
    task.json        # 步骤序列：每步含动作类型/定位证据/可变占位符标注
    screenshots/      # 录制时每步截图
    corrections.json  # 纠错记录（按步骤索引）


==================================================
四、分阶段开发计划
==================================================

每个阶段都能演示，用最小路径验证。

--------------------------------------------------
阶段 0：技术验证
--------------------------------------------------
目标：Windows 上跑通"录制->回放"最小闭环。

0.1 脚手架：Tauri 2.0 + Python sidecar（参考 ScreenClaw）；悬浮条仅"录制/停止/回放"三按钮
0.2 录制 MVP：pynput 监听鼠标键盘；每次点击截屏+抓 UI Automation 树；输出 recordings/
0.3 回放 MVP：读事件序列按坐标回放(pyautogui)

验证：记事本录制"输入文字+保存"能回放成功。

--------------------------------------------------
阶段 1：确定性编译
--------------------------------------------------
目标：编译后能适应窗口位置/分辨率变化，不死回放坐标。

1.1 编译器：关键帧提取(合并漂移)；定位证据生成(UI Automation锚点优先，百分比坐标+OCR兜底)；输出 task.json
1.2 执行器升级：按证据重新定位元素(非死坐标)；动作后截图简单验证

验证：浏览器"打开网站->搜索"，移动窗口后回放仍成功。

--------------------------------------------------
阶段 2：数据泛化与跨应用
--------------------------------------------------
目标：跑通国铁发货类场景--跨应用、数据每天变化。

2.1 数据泛化：编译时标注固定值/可变占位符；可变值绑定来源(上步输出或当前界面)；执行时动态取值
2.2 跨应用流转：窗口切换捕获与回放；Chrome/Edge 用 Playwright 补 DOM 定位；微信/邮件/Office 适配
2.3 等待机制：标记"等待外部事件"步骤，轮询目标窗口新内容；小窗显示"等待中"，支持手动继续
2.4 会话持久化：登录/2FA 标记为会话步骤，保存 cookie 后续自动注入

验证：录制"浏览器查订单->复制地址->微信发联系人"，次日换数据回放成功。

--------------------------------------------------
阶段 3：人在回路纠错与自愈
--------------------------------------------------
目标：实现"越用越聪明"。

3.1 中断请求人工：定位/验证失败时小窗变黄暂停；暴露"接管纠正"和"重新演示此步"两入口
3.2 纠错捕获：人工操作时记录{当前状态,正确动作,结果}，存入纠错库
3.3 修复合并：纠正编译为该步替代规则；自愈信任(借鉴skillwright：先隔离试用，验证后固化)
3.4 多遍演示合并：追加录制按起止应用一致性判定同任务，合并分支

验证：首次试运行失败处接管纠正一次，次日同类情况自动成功。

--------------------------------------------------
阶段 4：极简体验与安全
--------------------------------------------------
目标：达到 PRD 用户体验与安全标准。

4.1 悬浮条与任务库：录制/停止/任务列表；任务卡片(名称+状态+运行+定时)；状态小窗(步骤简述/黄/红)
4.2 定时执行：每日/每隔X小时调度，后台静默
4.3 安全：录制数据本地加密；密码框默认暂停人工输入、默认不保存；进程黑名单
4.4 性能：录制CPU<5%(事件驱动非轮询)；截屏压缩+关键帧策略
4.5 跨应用边界提示：录制时检测不支持组合即时提示

验证：普通用户无需文档，15分钟内完成首个跨应用任务；3次纠错后成功率>90%。

--------------------------------------------------
阶段 5：稳定性与发布
--------------------------------------------------
5.1 异常恢复：崩溃后恢复到最近成功步骤，断点续跑
5.2 执行日志：每次产出 REPORT(步骤/结果/暂停原因)
5.3 兼容性测试：Win10/11 + Chrome/Edge/微信/邮件/Office 矩阵
5.4 打包：Tauri 安装包 + Python sidecar 静态打包(PyInstaller)

验证：连续一周定时执行无人工干预成功率>90%。

五、技术选型
==================================================

==================================================
七、风险与对策
==================================================

风险1：UI Automation 在部分应用抓不到元素
  对策：两级降级(UI Automation -> 坐标+OCR)，都失败则暂停请求人工

风险2：数据泛化标注不准（误把可变值当固定值）
  对策：默认疑为可变，匹配失败即暂停，人工确认后写入纠错库

风险3：跨应用输入注入被安全软件拦截
  对策：background 模式优先；提供前台托管模式(快捷键切换)

风险4：LLM 编译质量差导致首次成功率低
  对策：编译后必须试运行验证，0纠错成功率<50%时引导追加演示

风险5：自愈修复错误（打错补丁）
  对策：借鉴 skillwright 自愈信任机制，先隔离试用，多次验证后才固化
