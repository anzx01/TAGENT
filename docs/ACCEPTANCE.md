# PRD 成功标准验收报告

日期：2026-08-15
环境：Windows 11（UWP Store 记事本），Python 3.14 sidecar，FastAPI 后端
依据：docs/p12.md 第 7 节「成功标准」

## 验收方法

量化指标全部通过自动化脚本验收（`python/tests/acceptance/`）：

| 脚本 | 验收指标 |
|------|----------|
| test_a_first_run.py | 首次试运行（0 纠错）自主成功率 > 50% |
| test_b_corrections.py | 最多 3 次纠错后自主成功率 > 90% |
| test_c_time.py | 完整用户流程总耗时 < 15 分钟 |

## 验收结果

### 标准 1：首次试运行（0 纠错）成功率 > 50% —— 通过（100%）

任务：记事本输入「Order <订单号> Ready」+ 回车 + 「Ship To: Beijing」，订单号标注为
`{{order_id}}` 变量并绑定剪贴板来源（模拟每天变化的数据）。

6 轮试运行，每轮改变剪贴板数据值与窗口位置：

| 轮次 | 剪贴板数据 | 窗口移动 | 结果 |
|------|-----------|---------|------|
| 1 | Order 88001 Ready | 是 | 成功 |
| 2 | Order 99302 Ready | 是 | 成功 |
| 3 | Order 10403 Ready | 是 | 成功 |
| 4 | Order 77504 Ready | 是 | 成功 |
| 5 | Order 66005 Ready | 是 | 成功 |
| 6 | Order 88106 Ready | 是 | 成功 |

成功率 6/6 = 100% > 50%。

### 标准 2：最多 3 次纠错后成功率 > 90% —— 通过（100%）

任务：记事本输入「Start」+ 回车 + 「hlelo」（第 2 步拼写错误，模拟用户操作有误；
player 设计上不对第 0 步应用纠错，防止误纠正任务入口，故错误置于第 2 步）。

- 0 纠错试运行：内容「Starthlelo」，任务失败
- 注入 1 次纠错（trigger=hlelo -> correct=hello）
- 纠错后试运行 6 轮，全部成功（内容「Starthello」）

纠错后成功率 6/6 = 100% > 90%。

### 标准 3：完整用户流程总耗时 < 15 分钟 —— 通过（42.2s）

模拟真实用户完整时间线并全程计时：
第 1 遍录制（Hello）-> 第 2 遍追加录制（Hello + 补录 World）-> 合并去重 ->
试运行 1 次 -> 注入 1 次纠错 -> 再次运行成功。

| 阶段 | 累计耗时 |
|------|---------|
| 第 1 遍录制完成 | 8.4s |
| 第 2 遍录制完成 | 16.0s |
| 合并完成（去重 1 步） | 16.0s |
| 试运行完成 | 27.8s |
| 纠错注入 + 再次运行成功 | 42.2s |

总耗时 42.2s < 900s（15 分钟）。含等待 UWP 输入管线落盘的固定延迟，
真实用户操作时间更短。

### 标准 4：用户无需阅读帮助文档即可独立完成首次任务自动化 —— 待人工评审

该指标无法完全自动化验收，建议由非开发人员在新装机环境按以下清单操作验证：
1. 点击悬浮条「录制新任务」，正常操作一遍任务
2. 点击「停止录制并保存」
3. 点击任务卡片「运行」按钮，观察状态小窗
4. 若中途变黄暂停，接管操作后点「继续，并记住我的做法」
5. 全程不提供任何文档或提示

配套自动化近似：验收 C 的完整流程（录制 2 遍 + 合并 + 试运行 + 纠错 + 再次运行）
在无文档指引下全部环节由脚本自主完成。
